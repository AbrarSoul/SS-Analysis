## Scope of closure and next engineering task

The audit document still lists unreviewed syntax, so its former blanket statement "reject any
candidate touched by an unhandled binding form" was too strong. I corrected the front matter to
describe the actual implementation: known exclusions are enforced; unreviewed forms are not
automatically rejected. That distinction is consistent with its existing limitations section.
No arbitrary new source should inherit the validation of these 11 pairs.

For the next fixed-development-set C/D implementation, use the reviewed selection and immutable
probe inputs, with source/builder/parser/probe hashes checked on cache load. Changed or additional
inputs need fresh admissibility review; a general automatic builder requires a separately enforced
supported-syntax boundary. The integration itself must offline-test:

1. Visible pass plus probe failure triggers repair within the same three-call budget.
2. Visible and both probe checks pass: accept and stop.
3. Budget exhaustion: retain failure; do not reset calls or silently accept.
4. Ineligible case: explicitly recorded visible-only fallback, still in the denominator.
5. Probe scan error: failure/error handling, never an ineligibility fallback.
6. Cache mismatch: reject or rebuild/review under a new version; never silently reuse stale input.

Count additional scans and any repair calls. Preserve A/B behavior and forbid hidden evaluation
files as generation/probe inputs. C/D inference remains a separate budget decision after this
offline implementation is complete. C3/C4 remain outside this work.
