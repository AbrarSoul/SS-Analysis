## Finding 1 — Medium: equal basenames overwrite one snapshot side

`pipeline/diagnostic_v2.py:387` constructs both destinations from `Path(input_path).name` in the
same directory. Distinct, valid inputs `input_vulnerable/function.py` and
`input_patched/function.py` therefore map to one snapshot file. Both original files pass initial
byte verification; the second write then overwrites the vulnerable snapshot with patched bytes.

The reproduced episode consumes three mocked generation calls, performs zero probe invocations,
and fails each attempt's integrity check. Snapshot listing contains only `function.py`, with
the patched content. This is deterministic internal overwriting, not a concurrent-writer claim.

Use distinct role-specific snapshot destinations regardless of caller basenames, preserving
appropriate language suffixes (or separate vulnerable/patched subdirectories). Verify the paths
are distinct before generation and add a same-basename, different-directory regression. Current
coverage artifacts use `vulnerable_probe.<ext>`/`patched_probe.<ext>`, so this reproduction does
not establish an effect on their historical measurements. The future CLI can use those canonical
names, but the runner should not silently corrupt valid independently supplied paths.

## Finding 2 — Medium: rejected integrity checks are counted as scans

`pipeline/diagnostic_v2.py:428` sets `scanner_invocations = 1` after both the drift and real-scan
branches. On drift, `scan_probe_fn` is deliberately never called. A probe check and a scanner
invocation are therefore being conflated again, specifically on this new branch.

Both the collision reproduction and a separate deliberately changed snapshot reproduce
**zero actual probe invocations but `resource_accounting.probe_scans == 3`**. The latter confirms
this is independent of filename handling. The gate correctly rejects those attempts and never
uses an ineligible fallback; only the scanner resource count is wrong.

Leave the count at zero when verification prevents scanning, and set it to one when the scan
call is actually entered (including a timeout). Record integrity failures separately if a count
of those checks is useful. Add a regression asserting zero scanner calls and zero reported probe
scans on persistent drift, while retaining correct timeout accounting and the three-call budget.

## Next step and limits

The snapshot solves the reviewed original-path mutation scenarios. A fresh output directory is
not an OS-level guarantee that no process can write inside it; the implementation assumes no
other authorized component writes to its private snapshot and defensively checks before each
use. This review does not claim protection against arbitrary concurrent writers or reopen that
threat model. The actionable findings above concern deterministic behavior of the code itself.

Correct the two small issues during the offline handoff: build the concrete manifest against the
reviewed 24-case source/disposition records and 11 eligible probe pairs, then wire strict loading,
snapshot creation, condition C/original construction and D/typed JSON, and recorded provenance
through the CLI. Test that complete path without models. Inference remains a separate budget
decision; no C/D success-rate improvement has been established by these engineering checks.
