## Finding 1 — High: validated probe text is not bound to the files actually scanned

`pipeline/diagnostic_v2.py:309` checks only whether `probe_result` is eligible and paths are
present; line 334 passes those independently supplied paths to the scanner. It never checks the
file contents against the validated object's strings or frozen hashes. The loader's new
verification therefore stops before the actual scanner boundary.

Reproduction: obtain a real `ProbeResult` using `load_probe_for_experiment` and a matching
synthetic manifest; materialize it; replace the vulnerable file with `def f(): return 999`.
The runner sends that changed source to the mocked scanner and accepts its passing result. This
demonstrates absent input binding, not a claim about Semgrep's behavior on that synthetic rule.
The existing tests supply nonexistent `/dev/null/...` paths, so they cannot catch this issue.

Required: materialize the validated probe into an immutable per-run directory, verify the actual
bytes before use, and record those hashes and manifest identity with the episode. Enforce the
approved source boundary at that materialization/runner adapter, rather than relying on a
docstring to prohibit arbitrary or hidden-input paths. Keep dependency injection for tests, but
add a real-file test showing a changed file is refused before generation/scanning. This can be
implemented in a shared adapter or the runner; the repository currently has no production
caller that enforces it. Missing frozen-manifest generation alone does not close this gap.

## Finding 2 — High: unresolved probe state becomes an accepted fallback

`pipeline/diagnostic_v2.py:309` implements ineligibility as "anything other than ProbeResult."
Passing `probe_result=None` makes the runner generate a rule, skip probe scanning, accept visible
success and report `probe_fallback_used=True`. A resolution/wiring error is thereby
indistinguishable from a reviewed ineligibility decision.

Required: require an explicit `ProbeResult` or `ProbeIneligible`, reject unknown/unresolved
objects before any model call, and validate case/language identity. Only a manifest-validated
ineligibility disposition may take the experimental fallback. Persist its reason on every
episode, including failure or all-decode-failure episodes; the current episode records
eligibility but drops the `ProbeIneligible.reason`. Invalid-input and explicit-ineligibility
tests should establish different outcomes.

## Finding 3 — Medium: A/B now imports the probe module

`pipeline/diagnostic_v2.py:28` adds a module-level `from dev_probe import ProbeResult`.
Consequently even A/B imports initialize the probe builder and tree-sitter grammars. A clean
subprocess importing only `diagnostic_v2` confirms `dev_probe` is loaded. A second subprocess
with a synthetic import hook representing unavailable tree-sitter packages fails that import.
No installed dependency was removed or altered.

This contradicts the protocol's explicit §5 rule that A/B must not import the probe module.
Keeping `run_model_case()`'s function body unchanged does not preserve its module import path;
passing existing tests with all dependencies installed does not verify that isolation.

Required: make probe imports local to the C/D path (or move the C/D runner to a separate module).
Test A/B import/use in a fresh process where probe imports are prohibited. This is a dependency/
isolation regression, not evidence of changed historical model scores.

## Remaining orchestration requirements, not completed by these tests

The new function is a real C/D retry implementation, but `main()` still dispatches only
`run_model_case`; no production caller connects the strict manifest loader, materialization and
C/D function. Before a run, that adapter must also bind C to original construction and D to
typed JSON, preserve corrected visible acceptance, and record selection/manifest/builder/
parser/probe provenance. The function's `condition` label alone does not enforce construction.

Probe timeouts need a durable policy. The default `scan_probe` uses `subprocess.run(timeout=120)`
without catching `TimeoutExpired`. Injecting that exact exception into the new runner makes it
exit after one generation call, before writing either `attempt.json` or `episode.json`. Returned
`scan_ok=False` dictionaries are handled correctly; this exception path is not covered by those
tests. A real `RawCaptureRecorder` may separately preserve the call; this reproduction does not
claim all call evidence is lost. Handle the exception as a recorded scan failure or durably mark
the episode interrupted, then resume without resetting already-consumed calls. A fresh call to
the function is not a resumption implementation: generation occurs before its existing-folder
check. Test the interruption path offline before any launch/resume procedure is used.

These are finite integration checks around already-reviewed fixed inputs, not a request for
another open-ended renamer audit. Next: close Findings 1–3 and the interruption recording path,
then build the concrete manifest against the existing reviewed 24-case source and 11 eligible
probe-pair hashes, and verify the complete adapter offline. New inference remains a separate
budget decision. No C/D success rate or E2E improvement has yet been measured.
