# Reproducibility Package (Priority 8, 2026-10-07 audit round 2)

A single index of every artifact needed to reproduce this study's reported numbers, and an explicit
list of what is NOT available and why. Nothing in this file is duplicated elsewhere — every entry is
a path into the existing repository, not a copy. See `Research_Log/Correction_Log.md` for the full
narrative history behind each correction referenced here.

**Note on paths in this file, for readers of the public repository specifically**: this document was
written against the original private working repository's layout. In this public repository, the
curated plain-text analysis reports it refers to under `results_corrected/*.txt` are at
`analysis_reports/*.txt` instead; `results/` and `results_corrected/`'s raw per-call JSONL logs are
not included here at all (see the top-level `README.md`'s "What's deliberately not included"
section) — the scoring scripts in §2 below are included and will regenerate those reports from raw
logs if you have or recreate them.

## 2. Scoring and correction scripts, in dependency order

Run in this order to reproduce `results_corrected/` from `results/` and the benchmark files above:

1. `python pipeline/compute_variant_vulnerable_lines.py` — automated line-range inference (produces the 571 `"high"`-confidence entries; the 29 `"manual"` entries are already baked into `variant_vulnerable_lines.jsonl` and are not regenerated by this script)
2. `python pipeline/rescore_variant_location.py` — retroactively applies finding-location-correctness to every `variant_vulnerable_1/2` sample record (Finding 1's fix), reading `results/`, writing `results_corrected/`. No new Semgrep/LLM calls.
3. `python pipeline/build_step4_tables.py` — the explicit 5-row end-to-end table (§7.9), output captured at `results_corrected/step4_tables_report.txt`
4. `python pipeline/analyze_section22_corrected.py` — the 7 predefined comparisons + repo-aware bootstrapping (§7.8), output captured at `results_corrected/section22_corrected_report_round2.txt`
5. `python pipeline/analyze_section22_subgroups_corrected.py` — subgroup analysis (§22.4), output captured at `results_corrected/subgroup_corrected_report.txt`
6. `python pipeline/analyze_phase5_stability.py` — stability experiment (§7.3), reads `results_corrected/runs_phase5_stability_rep{1-5}/`

Each script's own docstring states its exact inputs/outputs and every correction applied to it; none of this is re-explained here.

## 6. Missing artifacts, stated explicitly (per Priority 8's instruction)

- **Generated rule YAML text** for the primary benchmark, stability experiment, C2, C3, and C4 (§3
  above) — not retrievable from existing data; would require new LLM generation calls to recreate,
  which this audit deliberately avoided per the user's own stated preference to recalculate from
  existing data rather than regenerate rules.
- **Per-case token/output/latency data** for the primary benchmark and C3/C4 (§3 above) — same
  limitation, disclosed in §7.8 and here, not recoverable.
- **The specific failure reason (parse vs. discrimination) for most primary-benchmark autogrep-condition
  rejections** — corrupted by the diagnostic-text bug documented in `Implementation_Log.md` Section
  12.30; the real pass/fail outcome (`semgrep_valid`) is unaffected and correct, but the human-readable
  "why it failed" text for ~60-77% of rejected cases per model cannot be recovered.
- **Pilot screening numbers (§6)** have not been recomputed with Finding 1's location-correctness fix
  — the pilot only informed early prompt-template/model-direction decisions, not any headline
  comparison, so this was judged out of scope for this audit, but is a disclosed inconsistency between
  §6 and everything downstream of it (`Paper_Draft_Notes.md` §11).
- **A direct case-level investigation of why `qwen2.5-coder:32b` and `codellama:7b-instruct-fp16`
  each score above their own entire 5-repeat temp-0.2 range at temp-0** (§7.3's remaining residual) —
  not run; would require inspecting individual sample-level flips for these two models specifically.
- **A controlled rerun isolating role separation from the other 3 C2/C3/C4 confounds** — not run; per
  the Priority 8 scope decision (`Paper_Draft_Notes.md` §10), not needed under this document's actual
  (non-causal) claims, but would be required before any future paper claims role separation itself is
  causal.
- **A rerun against a corrected Autogrep wrapper that accepts composite Semgrep patterns**
  (`patterns:`/`pattern-either:`/`pattern-not:`) — not run; per the Priority 8 scope decision
  (`Paper_Draft_Notes.md` §10), this document's conclusions are explicitly scoped to the tested
  Autogrep implementation as configured, not to LLM-to-Semgrep rule generation as a general capability
  claim.
